# PUIMS — Threat Model (v1.0, Milestone 8 review)

Method: STRIDE over the data flows in `00-MILESTONE-0-PLAN.md` §4. Re-reviewed at every milestone; full review in Milestone 8.

**Assets**: patient identity and clinical records (PHI); staff accounts and roles; audit history; legacy workbook during import; backups; devices that may (from M7) hold offline data.

**Trust boundaries**: browser ↔ PUIMS server (TLS); server ↔ PostgreSQL; device local storage; import file ↔ staging; hospital LAN ↔ internet.

## Residual risks (Milestone 8)

- **No real patient data yet.** Release gate: hospital IT, DPO/privacy and clinical governance approval (handoff checklist §H). Nothing in this repository has been through a hospital security assessment or penetration test.
- **Offline (T-11):** while a capture page is unlocked, the key is in memory — anyone using that unlocked browser can read the snapshot and queue. A revoked device that never reconnects keeps its (encrypted) data; it cannot be wiped remotely. Browser storage can be cleared by the user (unsent entries would then be lost — the page says to document on paper if unsure). Approve only managed devices with OS-level encryption and screen lock (U-03).
- **Import (T-13):** a crafted .xlsx could still use significant memory while being decompressed; upload is Chief-only and rate-limited.
- In-memory rate limiter is per process; per-account DB lockout still applies. Use a shared store or reverse-proxy limits before running more than one instance.
- Style `'unsafe-inline'` in the main app CSP (scripts are nonce-only).
- "Device" = browser-profile cookie, not hardware attestation.
- Pulmonologist sign-off is a recorded attestation of a wet signature, not an electronic signature (U-18).
- No self-service password recovery (by design); depends on Chief RT availability.
