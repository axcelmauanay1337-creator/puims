# ADR-0007: Interim offline capture (encrypted IndexedDB, short leases, per-device approval)

Status: Accepted for development/UAT (Milestone 7). **Production use requires U-03 approval** (hospital IT + DPO).

**Context.** Wards lose connectivity; RTs still give nebulizations and change circuits. The handoff forbids last-write-wins and silent loss, and requires honesty that IndexedDB is not encrypted by the browser.

**Decision.**

- Option (a) of ADR-0003: a framework-free, statically served capture page (`/offline-capture.html`, strict CSP, cached by the service worker) using WebCrypto AES-256-GCM over IndexedDB. Option (b) (Capacitor + encrypted SQLite) is not built.
- Scope: only nebulization dose outcomes and tubing replacements; snapshot limited to pending doses (2 h back → lease end) and active ventilator encounters.
- Per-device approval by the Chief RT (step-up). Refused in `lan`/`cloud` profiles unless `PUIMS_OFFLINE_POLICY_APPROVED=true`.
- Lease ≤ 12 h and ≤ session. The device key is generated by the server, stored there encrypted with `PUIMS_DATA_KEY`, imported on the device as non-extractable and **kept in memory only**; after a reload it is re-released only to the same staff + device + valid session. Revocation stops release and sync.
- Sync goes through the normal validated write functions, idempotent by client id; every entry is kept in `sync_event` with an outcome; conflicts (already documented, clock skew > 5 min, outside the lease) wait for human review.

**Consequences.** A reload while offline locks the page (entries stay, encrypted) until the user reconnects — a deliberate trade-off: no key ever rests on the device. Patient data is visible to anyone using the unlocked page. Remote wipe of an offline device is impossible. These limits are shown in the app and in `docs/OFFLINE_BEHAVIOR_MATRIX.md`.
